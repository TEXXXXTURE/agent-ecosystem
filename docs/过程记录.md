# Agent 生态总系统 · 过程记录

> 只记影响结果的过程：备选、推演、否决理由、关键取舍、未决问题。个人使用痕迹与运维过程留在本地完整版（心路历程），本文件只记产品向决策。

## 推演脉络（按时间追加，不覆盖）

### 2026-10-01 · 总纲立项：平级项目 → 集成层

- **背景**：所有已有项目从搭建视角**全部平级**，各自承担不同产出逻辑；"组起来"的职责需要一个独立项目承担，不吞并任何工具。
- **备选方案**：
  - ① workbench 升级为总系统 → **否决**：owner 拍板平级原则——workbench 是展示/外壳叶片，与其他工具平级；总系统职责另立项目更清晰。
  - ② 新建独立总纲项目 agent-ecosystem → **采纳**。
- **关键取舍**：总系统 = 集成层，只做编排 + 契约 + 挂载；工具叶片 = 引用指针不镜像；只在 project-vault 立项。
- **未决问题**：① 意图路由与 scene-express 表述路由的关系；② 首批产出物 schema 字段；③ 与 workbench 契约对齐粒度。

### 2026-10-08 · 督促互审闭环：19 案例调研（详见 docs/调研/督促互审闭环调研报告.md）

- **背景**：用户判定 Munder Difflin（外部编排软件）靠文件传输、无范式突破，非原生方案；转向自修集群规则。三环节拆解：① AI PM 已有（project-pm-tracker）② 项目管理已有（project-vault）③ **缺督促-互审-闭环**。
- **调研结论**：六框架（MetaGPT/ChatDev/AutoGen/CrewAI/LangGraph/OpenAI SDK）无一内置"督促者"角色——催由契约顺序/图边/handoff 自然产生，**"强制 vs 自然引导"立场被业界验证**；闭环里唯一该写死强制的只有产出物校验器。
- **关键取舍**：不做多轮互审循环——**方向问题升级 owner、机械问题机器兜底**（owner 说话不烧 token，且最懂要什么）。

### 2026-10-08 · 精简 6 步闭环定稿（owner 拍板）

```
① PM 产出方案 + 机器 schema 校验（免费）
② owner 审方案拍板（0 token，替代方案互审循环）
③ 编码执行（N 次）
④ 出问题分两档：机械→自解+机器兜底；方向→直接升级 owner（0 token，替代编码互审循环）
⑤ 机器校验过→交付；失败→带原因回③
⑥ 可选互审 + 落痕（0-1 次调用）
```

- **动因**：原 12 步设计 token 消耗大，被用户否决；互审循环每轮 = 2 次模型调用，2-3 轮即 4-6 次，是最大开销源。

### 2026-10-08 · 规则形态定稿：混合三明治（详见 docs/调研/规则形态调研与仓库结构草案.md）

- **背景**：用户问规则写进 AGENTS.md 还是编排层。三路形态调研（指令文件层 / 编排层 / 混合形态与规则验证）收敛：**判断留给 NL、兜底留给程序**。
- **关键取舍**：
  - 薄门面 `AGENTS.md`（6 步一句话 + 命令，跨工具自动读，零注册）+ 厚人设 `docs/soul.md`（6 步细则）；
  - 程序约束 `contracts/`（schema + 校验器 = 唯一强制点）+ `orchestrator/`（显式状态机，不写进 prompt 让 Agent 自觉）；
  - 硬执行不进指令文件（Claude 官方：CLAUDE.md 只塑造行为，permissions.deny 才是硬约束）；
  - 两档分流、owner_gate 做成程序原语；规则测试 = 确定性优先（schema 单测 / 终态断言 / 分流断言 / 终止条件单测）+ 规则文件 lint 进 CI，LLM-judge 作第二档。
