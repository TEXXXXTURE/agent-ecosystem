## 二、叶片声明形态（2026-10-08 定稿）

每个叶片一个 Markdown 文件，**frontmatter 写结构化元数据 + 正文写"怎么干活"的自然语言**（参照 Claude Code subagents 混合文件）：

```markdown
---
name: project-pm-tracker
type: leaf
kind: 规则维护型
description: "产品决策叶片：把想法/材料转为有依据的方案、PRD、优先级、评审。何时选我：需求取舍、方案评审、PRD 起草。何时别选我：纯执行、已定方案的技术实现。"
input_contract: ["project_context", "requirement_material"]
output_contract: ["pm_plan"]
tools: []            # 工具白名单（可选）
pointer: ".user_skills/project-pm-tracker"
---

# 正文：怎么干活（自然语言，接契约即开工）
```

- 程序按 frontmatter 发现、路由（读 `description` 的"何时选我 / 何时别选我"）、注入正文与工具白名单。
- frontmatter 解析失败 → 拒载并记日志（加载期闸门）。
- 叶片只声明"我吃什么、我产什么"，能力细节留在产品仓。

## 三、分类说明

- **累积型**：产出物进入长期记忆/资产库，供检索与反哺。
- **产出型**：产出物是交付成品（视频成片），进入展示/分发。
- **处理型**：产出物是"转化结果"，特征是"输入即输出"的即时加工。
- **展示型**：workbench 是外壳，消费其他叶片的产出物做渲染。
- **规则维护型**：project-vault 与契约注册表维护系统本身的契约与元规则。

## 四、挂载规则（新增叶片）

1. 新工具接入 = 在本表登记一行 + 新增 frontmatter 声明文件（输入/输出契约 + 指针），不动任何既有叶片与编排代码（FR-04 验收）。
2. 叶片只声明"我吃什么、我产什么"，能力细节留在产品仓。
3. 契约变更：先走 ADR（契约稳定，NFR-01），再同步本表。
