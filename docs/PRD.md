# Agent 生态总系统 · PRD

## 一、项目理念与设计方向（纲领，指导所有决策）

- **产品是什么**：把**平级的能力单元**（工具 / Agent / 项目）组织为可组合总系统的**集成层**——产出物契约驱动：编排 Agent 按契约路由传递，契约注册表是规则本体，workbench 是展示外壳。终极目标是"贾维斯式第二大脑"的工程实现。
- **为谁**：owner 单人。所有项目平级，本项目只负责"组起来"的总系统工作（编排 + 契约 + 挂载），不吞并任何工具。
- **决策准则**：
  1. **产出物是最小公约数**：能力单元只通过产出物交流——输入契约 → 输出契约；不互相依赖、不融合程序。
  2. **契约先行且稳定**：契约变更影响所有叶片，扩能力 = 造新工具插进契约注册表。
  3. **展示层铁律（承 workbench 理念 §1）**：总系统不承载业务逻辑；展示全部交给 workbench 外壳。
  4. **路径稳定度决定传递器**：固定路径 = 程序管道（确定、快、零幻觉）；动态路径 = 编排 Agent（灵活、可应变）。
  5. **叶片是引用不是镜像**：工具叶片清单只存产品仓指针，不复制内容（承 project-vault §11）。
  6. **一切皆 schema**：契约注册表与 second-brain 知识地图共享同一套 ontology 语言。
  7. **先查范式再动手（固定流程）**：制作任何工具 / 功能 / 设计前，先检索现有范式、已有工具与可借用思路，优先复用成熟方案；调研结论入项目记录。固化于 soul.md 规则一。
  8. **判断留 NL、兜底留程序（规则形态，2026-10-08 定稿）**：规则以混合三明治形态存在——薄自然语言门面（AGENTS.md）+ 厚人设（soul.md）+ 程序约束层（contracts/ 校验器 + orchestrator/ 显式状态机）+ 确定性测试。硬执行不进指令文件。

## 二、一句话定位

**Agent 生态总系统 = 集成层**：编排 Agent（意图路由 → 任务分解 → 契约匹配 → 传递 → 校验 → 循环）+ 契约注册表（规则本体）+ 工具叶片挂载；workbench 是它的展示外壳，second-brain 是它的记忆。
